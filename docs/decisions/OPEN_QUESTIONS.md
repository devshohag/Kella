Full Identity EF stores would add tables the spec does not list. | Decided |
| 2026-11-08 | Refresh token storage | Refresh tokens are stateless JWTs (`typ=refresh`, 30 days) in an httpOnly cookie; logout clears cookies. No `refresh_tokens` table until revocation lists are needed. | Decided |
| 2026-11-08 | Incident acknowledgement mechanism | Stored via `acknowledged_at` (timestamptz nullable) and `acknowledged_by` (text nullable) on `incidents` table rather than overloading `status` (SPEC §6 strictly specifies `open|contained|resolved`). Supports 10-min escalation timer per SPEC §12. | Decided |
| 2026-11-09 | Server outbound IP reputation monitoring | Server facts currently do not expose a distinct list of outbound sending IPs; `IpReputationService` checks `servers.PublicIp` as the sending IP per SPEC §9 & §17. | Decided |
| 2026-11-09 | Postfix smtpd SASL authentication failures and account takeover | Standard Postfix smtpd logs `warning: ... SASL <method> authentication failed` and `disconnect ... auth=0/1` with client IP, but does not log the attempted username. If a username is available in the log line, the agent extracts it into `Attrs["user"]`; where no username is available, SMTP-only brute force does not feed `mail.account_takeover` (which requires target mailbox username per SPEC §9). SMTP-only failures feed `mail.bruteforce_ip` by source IP. Dovecot authentication failures log `user=<...>` and feed `mail.account_takeover`. | Decided |
